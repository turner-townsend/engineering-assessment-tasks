# Take-Home Briefs

Four take-home tasks framed as **product stories**: from the user's perspective, with business
context and acceptance criteria. The engineer translates the story into an implementation against
the base app.

Each brief is a **marked take-home task**. It is scored as part of your application.

## How to read a brief

Each brief has the same shape:

- **The team & the ask** - who you're working with and the user story.
- **Why it matters** - the business value in the construction-controls context.
- **What good looks like** - acceptance criteria in `Given / When / Then` form (outcome, not implementation).
- **Things to keep in mind** - light guardrails: scope, the 90-minute timebox, what already exists.
- **Handing it over** - how to submit.

## Common rules

- Submit a branch or PR; keep existing features working.
- Use the existing stack; tests proportional to scope.
- AI and tooling are allowed if disclosed in `SOLUTION.md`.
- Include a short `SOLUTION.md` (decisions, trade-offs, what you'd do next).
